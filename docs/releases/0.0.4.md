## Changes

- Cleared message composers and reverted form choices can qualify for automatic sleep without navigating away. Unfinished drafts, unsaved deletions, selected files and uncertain editor state remain protected.
- Completed calls and captures no longer leave a cached activity flag blocking sleep. Capture copies, including cloned and repackaged streams, stay protected while live.
- If a system panel retains an unloaded page view, Barc replaces its old document and history with a blank page. The tab keeps its separate restoration state and profile cookies. Views handed to a new owner or attached to a surface are excluded from cleanup.
- Performance separates the Barc app, networking, graphics, auxiliary pages and tab processes. Process RAM includes WebKit and caches; shared processes are labelled and counted once. WebKit does not expose an exact engine baseline or tab-only allocation.
- Page details and page tooltips explain why automatic sleep is deferred.

## Verification

Regression checks passed across two runs covering **2,459 distinct tests**. The broad run covered 2,452 tests; a separate 40-test lifecycle run included the seven timing-sensitive checks excluded from the broad run. Opt-in checks remain disabled in ordinary runs.

Checks include the real one-minute scheduler, eight repeated edit/clear/sleep/wake cycles, stopped and cloned native capture tracks, retained-view cleanup, restoration of history and private session cookies, transfers and protection of new view owners. The optimized application built and passed strict signature verification.

WebKit controls process reuse and cache reclamation. These fixes address reproduced retention and sleep-blocking bugs; they do not impose a fixed RAM limit on websites.
